# Portable reproduction

`make install` installs the pinned DuckDB CLI (`duckdb-cli==1.5.2`). The Python
DuckDB binding does not install the executable used by the two SQL rules.
No separate system DuckDB installation or runtime download is required.

## Validation partitions

NumPy 2.4.3 uses different unstable argsort implementations on ARM, AVX2, and
AVX-512 CPUs. scikit-learn 1.8.0 GroupKFold uses argsort to break ties between
protein groups of equal size. Consequently, pinning library versions and random
seeds alone did not preserve the archived train/test partitions.

`src/regional_code_paper/core/validation_folds.json` freezes the original
partitions: scanner outer folds, each outer training set's three inner folds,
regional-code folds, and all 15 region-definition sensitivity cohorts. These
were recovered using the original locked NumPy and scikit-learn versions on
Warrior's AVX-512 node alt1. Every scanner outer assignment was checked against
the archived prediction table at commit c03b09b. No labels or outcome metrics
were used to choose the partitions.

The shared splitter identifies a cohort by a SHA-256 hash of the split count
and sorted protein identifiers with their tile counts. It rejects unexpected
cohorts instead of silently creating a different experiment. Changing the
scientific cohort requires explicitly specifying and reviewing new partitions.
The manifest is a declared DAG input for every model-fitting rule. Model fits
still use one numerical thread, with parallelism across folds and analyses.
The audit also checks scanner AUROC/AP and regional composition/geometry metrics.
The original numerical reference values and tolerances are unchanged.

The checked-in manifest is an input, not something to regenerate for each run.
Its recovery script is retained as `scripts/recover_validation_folds.py`. On the
reference AVX-512 runtime, after feature preparation, it accepts
`--archived-results /path/to/c03b09b/results --output /path/to/new-manifest.json`.
It refuses to write a manifest unless every scanner outer fold agrees with the
archived table. The full audit then tests the recovered regional and nested
scanner predictions against their original numerical references.

## Older HPC hosts

The locked scientific wheels need a modern Linux runtime. On Warrior's EL7
hosts, run them inside Apptainer with Python 3.12 on Debian bookworm. The tested
container is `docker://python:3.12-bookworm`; record its SIF SHA-256 for a run.
For exact replay, preserve that SIF: the Docker tag itself can change.

```sh
module load apptainer/1.2.2
apptainer pull python-3.12-bookworm.sif docker://python:3.12-bookworm
sha256sum python-3.12-bookworm.sif
apptainer exec --bind /wsu:/wsu python-3.12-bookworm.sif bash -c '
  export PATH="$HOME/.local/bin:$PATH"
  export UV_PYTHON=/usr/local/bin/python3.12 UV_PYTHON_DOWNLOADS=never
  export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
  make install
  make check
  make reproduce SNAKEMAKE_ARGS="all --cores 96 --resources mem_mb=327680"
'
```

Request the CPU and memory allocation through the scheduler first. The command
assumes the repository is the current directory, uv is installed, and the frozen
input bundle is present. The input manifest checks the same data contract.

## Verified clean run

On 13 October 2026, Warrior job 40603311 rebuilt the complete DAG from an empty
results directory on csy2 (AMD EPYC 7643, AVX2), requesting 96 CPUs and 320 GiB.
It finished all 85 steps in 19 minutes 34 seconds. The same checksum-verified
input tree used in the original failed run was reused; no feature caches,
model fits, or retained result tables were reused.

The expanded audit passed all 20 numerical checks and all 18 figure-file
checks. Follow-up job 40603314 passed 23 unit tests and compared the rebuilt
outputs to commit c03b09b: all 82 ledger claims, all 15 sensitivity rows, and
both prediction tables (49,394 regional tiles and 314,040 scanner tiles) matched.
Every parsed prediction score had zero absolute difference. All input file and
directory hashes matched. `results/audit/warrior_comparison.json` records the
comparison. The original expected values and audit tolerances were not relaxed.

This verification covers the figures generated by the existing analysis DAG.
The revised manuscript figure set from 11 October is a separate editorial asset
package: several panels retain authored vectors, so it is not represented as a
fresh reconstruction of those legacy analyses.
